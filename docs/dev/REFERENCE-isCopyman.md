# 参考资料：isCopyman/zotero-bilingual-reader

- 读取时间：2026-11-09，方式：`gh`（repo view / issue view / release view / README API）。
- 许可证：GitHub API 返回 **MIT**（`licenseInfo.key = "mit"`）。按任务要求**不复制其代码**，只记录问题、解法与思路。
- 注意：该仓库与我们的上游 quillamio/bilingual-reader **同名不同实现**。isCopyman 版是"自绘双语页盖在 PDF 标签页上"的路线；我们上游是"往 Zotero 阅读模式 SDT iframe 里插入译文块"的路线。两者架构不同，借鉴时注意区分。

## 1. 他们的架构（README 证据）

- 双语页是独立视图，默认盖在 PDF 标签页上（可切换回 PDF），也可开新标签页；**不改动原 PDF、不新增附件**。
- 按**句**对齐（粒度可选 1/2/3 句或整段，切换粒度不需重新翻译）；我们是按段。
- 两种正文来源：Zotero 结构化文本 或 MinerU 解析；MinerU 文本**按字符对齐**到 Zotero 文本，因此 MinerU 来源下也能显示/创建 PDF 高亮、定位。
- 译文缓存在 Zotero 数据目录的**独立文件**（我们上游存在 prefs 里）。
- 高亮就是 Zotero 原生注释（存数据库），双语页与 PDF 阅读器双向显示。

## 2. Issues（仅 1 条，#1，OPEN）

用户提出的优化点（对我们都有参考价值）：

1. MinerU 与翻译 AI 应有**独立插件配置页**，不要堆在主页面 → 我们坚持所有配置进 Zotero 设置页。
2. AI 翻译要支持 **API + 自选模型**，CLI harness 模式"能用但不透明" → 我们的 Provider 层（step 3）正是这个方向。
3. **提示词可自定义**；默认中文译文对公式、上下标、公式渲染不友好 → prompt 可配置 + 公式不译的策略要写明。
4. 批注希望继承 style 插件的颜色样式 → 超出我们范围，记录备查。

## 4. 对我们步骤的具体借鉴清单

- **step 4（显示模式）**：四种模式（英/对照/左右/中）+ 快捷键 1-4 是他们验证过的交互；单语模式下看另一语言有"悬浮气泡/段下展开/点击切换/不提示"四档——我们的"仅译文/仅原文"模式可借鉴"悬停peek"作为可选增强。双栏对应句标记用整组框而非每句小框。
- **step 4 风险**：他们放弃 SDT 注入、自绘页面，侧面印证 SDT 内部路线做复杂布局（双栏）的版本敏感性；我们坚持注入路线就要把双栏做成可降级的实验特性。
- **step 5（触发）**：段落旁小按钮（未译→翻译、已译→重译、有失败→只重试失败）比悬停自动翻译更可控；失败句一键重试入口在工具栏（"失败 N 句，重试"）。**浮层避开阅读器工具栏拖动区**（v0.1.21 的坑）。
- **step 3/7（缓存与术语）**：文本归一化去重（v0.1.18）；术语统一是"首翻先定关键术语，之后每批带上 + 全局术语表"——与我们 prompt 注入路线一致。
- **step 8（侧栏）**：他们的侧栏是目录/书签/注释，不是聊天；但"批注卡片停笔自动保存"的交互可参考。
- **设置分层**：每篇记忆显示类设置、全局共享引擎/主题类设置（v0.1.24），值得我们照抄这个分层原则。
