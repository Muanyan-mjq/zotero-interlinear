## Google 翻译"全部失败"根因与修复（fix/google-batch 分支，本地未 push）

- **根因（重大）**：Zotero `HTTP.request` 对 429/5xx 有内置自动重试，默认最长 1 小时（`errorDelayMax=3600000`）。Google 限流后每个请求陷入 Zotero 内部重试循环，直到被插件外层超时杀掉 → 用户看到"全部翻译失败/超时"。佐证：读 `C:\Program Files\Zotero\app\omni.ja` 里的 `chrome/content/zotero/xpcom/http.js`（提取到 `.scaffold/zotero-src/`）。
- **修复**：`NO_REDIRECT_OPTIONS` 增加 `noRetryOnThrottle: true, errorDelayMax: 0`，限流完全由插件接管。
- **multi-q 批量**：googleProtocol 增加 `buildGoogleQueryMulti`/`parseGoogleMultiResponse`；google.ts 增加 `requestGoogleTranslations`；provider 增加 `translateBatch`；bilingualReader.translateJob 优先原生批量，形状异常回退 marker 批量。请求数降 ~6×。
- **限流冷却**：`GoogleThrottleError`（含 cooldownMs，验证码 60s）；worker 捕获后任务放回队列、显示冷却状态、等待后自动重试（最多 2 次），持续限流才中止并给明确提示（新 ftl 键 paragraph-throttle-cooldown / paragraph-throttle-stopped）。
- **模型 provider 重试**：secureRequest 增加 `requestWithRetry`（429/5xx，1s/2s/4s），接入 openai/claude/gemini/chat/ollama；`src/utils/retry.ts` 提供 retryDelayMs/isRetryableStatus。
- **Zotero HTTP 行为事实**：429 不 opt out 会挂起（timeout 选项也不触发）；302 + followRedirects:false 会 resolve 一个 status=3xx、只有 Location 头的替身对象。
- **e2e 基建**：mock-llm-server 增加 `/translate_a/single`（multi-q）、`/__control`、`/__stats`、LLM 首击 429；test-e2e 新增 360 段批量对齐/限流/验证码用例 + probe 子目录；`INTERLINEAR_E2E_ENTRIES` 指定子目录。跑 e2e 需 `ZOTERO_PLUGIN_ZOTERO_BIN_PATH="C:/Program Files/Zotero/zotero.exe" CODEBUDDY_SAFE_DELETE_ENABLED=0`（shim 拦 scaffold 清 `.scaffold/test/data/translators`）。
- **测试结果**：单测 215 全过；e2e 4/4（探针、四模型协议+重试、360 段 60 请求、限流冷却+恢复）。

## 修复：单段/悬停翻译完全不可用（用户明确要求「主按钮保持全文，单段要能用」）

- **根因（已用本机 Zotero 10.0.8 的 `app/omni.ja` 核实）**：`resource/reader/reader.js` 里 `container.id='sdt-content'`、`#sdt-content > [data-ref-path]`、view 有 `_iframeDocument`，但 `_primarySDTView`/`_secondarySDTView` 在 web app 的 ZoteroReader 实例上，**只有开启阅读模式才非 null**。插件 `watchReaderInteractions` 只在 `#sdt-content` 已存在时挂控制器，3 秒有界重试 + `interactionWatchers.has(reader)` 一次性短路 → 阅读模式晚开就永久挂不上。而唯一能开阅读模式的入口是工具栏全文翻译（`ensureReadingMode`），全文翻完每段已有译文块又被 skip → 用户「一翻译就是全文，任何单段都不行」。
- **改动**（`src/bilingualReader.ts`，199+/61-）：watcher 可重入（已有 watcher 也重试）；加 `observeForContent` MutationObserver 观察 outerDoc 与每个 SDT doc；重试窗口扩到 60s 且挂上即停；`ensureReadingMode` 两个分支都调 `ensureReaderInteractions`；新增 `enterParagraphTranslationMode`（只开阅读模式+装样式+挂控制器，**不 dispatchToggle / 不跑 run / 不提前装 observeReadingLayout**，避免原生高亮回归）；工具栏右键菜单加 `paragraph-mode`；PDF 视图下按单段快捷键由 `onBootstrapKeyDown` 引导进入单段模式；私有文档访问统一走 `getSDTViewDocument`。中英 ftl + i18n.d.ts 同步。
- **测试**：新增 `test/readerInteractionWatch.node.test.mjs`（8 条源码级回归断言，已加入 `test:unit`）；tsc / lint / 相关单测 64+8 全过。
- **环境要点**：跑 `test:review` 需要 `ZOTERO_PLUGIN_ZOTERO_BIN_PATH` 且 shim 会拦 `emptyDir`；另一会话记录的解法是 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，我用的是「把 `.scaffold/test` 整个重命名 + 停掉带该路径的孤儿 Zotero 进程」。
- **注意**：本工作区有并发会话在改 Google 批处理（`providers/google*`/`settings.ts`/`secrets.ts`），其改动使 `test:unit` 出现 3 条 Google 断言失败（endpoint `single`→`t`、client `gtx`→`it`），与本次修复无关；`localeParity` 不在 test:unit 内且原本就有 1 条失败。
